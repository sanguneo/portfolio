# Portfolio design brief

## 1. Product purpose

Present the complete portfolio as a readable, print-ready record of projects, with original descriptions, technical notes, dates, and capture images intact.

## 2. Primary user

People reviewing the work on a laptop, phone, or printed PDF who need to understand the breadth and evidence of the projects quickly.

## 3. Principles

- Preserve project meaning and evidence while changing presentation.
- Let navigation and typography create hierarchy before decoration.
- Treat print as a first-class reading mode, not an export afterthought.
- Make captures inspectable without making them carry the whole explanation.
- Prefer an authored archive over a generic portfolio template.

## 4. Success metric

A reader can move from cover to index to any project, read Korean copy without clipping, inspect capture images, and use the same document at 375px, 768px, 1280px, and A4 print without content loss.

## 5. Out of scope

- Rewriting or correcting `data.json` content.
- Adding, replacing, or generating project capture images.
- Publishing internal product screens that are not already in the repository.
- Removing the A4 print flow.
- Introducing a frontend framework or build dependency.

## 6. Learned constraints

- **2026-07-29** — Keep only the existing portfolio content and capture images as the source material, while rewriting the presentation layer end-to-end. *Why:* the visual design should change without changing the portfolio evidence or project meaning.*
